# Step 4.1 - IA 6 - Compatibilite Rewards Staged Rules

## Objectif

Garder les APIs rewards staged existantes fonctionnelles pendant la migration,
en les faisant compiler vers le meme modele de mutations que `on_commit`.

## Contexte a lire

- `official_plugins/sdk/runtime/src/rewards/rules.rs`
- `official_plugins/sdk/runtime/src/rewards/control.rs`
- `official_plugins/sdk/runtime/src/rewards/lua.rs`
- `crates/sdk-api/src/api/rank.rs`
- `crates/sdk-api/src/api/difficulty.rs`

## Fichiers a modifier

- Modifier: `official_plugins/sdk/runtime/src/rewards/rules.rs`
- Modifier: `official_plugins/sdk/runtime/src/rewards/control.rs`
- Modifier: `official_plugins/sdk/runtime/src/rewards/lua_tests.rs`

## Travail

1. Identifier les staged reward rules actuelles.
2. Mapper les regles Berry supportees vers `RewardMutation`.
3. Garder les regles souls en stub explicite.
4. Ajouter un warning clair pour toute regle non supportee.
5. Documenter la transition dans les tests.

## Contraintes

- Ne pas supprimer l'API existante.
- Ne pas pretendre que souls est implemente.
- Ne pas melanger rank/difficulty dans rewards si la condition n'est pas evaluee
  au runtime.

## Tests a ajouter

- Une ancienne regle Berry donne la meme mutation que `on_commit`.
- Une regle souls retourne un stub loggable.
- Une regle inconnue ne panique pas.
- Les tests existants `sdk_runtime_rewards_builds_*` continuent de passer.

## Verification

Lancer:

```powershell
cargo test -p oppw4-sdk-runtime-plugin rewards
cargo test
```

Resultat attendu: tous les tests passent.

## Definition of done

- Compatibilite conservee.
- Les nouveaux chemins core sont la source de verite.
- Les stubs sont explicites dans logs/tests.
