# Step 2.1 - IA 3 - Event Bus Runtime Interne

## Objectif

Ajouter un bus d'evenements interne a `sdk.runtime` pour dispatcher des events
types vers plusieurs handlers, sans appeler Lua directement depuis les hooks.

## Contexte a lire

- `official_plugins/sdk/runtime/src/runtime/signals.rs`
- `official_plugins/sdk/runtime/src/rewards/control.rs`
- `official_plugins/sdk/runtime/src/mission/difficulty/control.rs`
- `official_plugins/sdk/runtime/src/mission/rank/control.rs`

## Fichiers a creer ou modifier

- Creer: `official_plugins/sdk/runtime/src/runtime/core/events.rs`
- Creer: `official_plugins/sdk/runtime/src/runtime/core/bus.rs`
- Modifier: `official_plugins/sdk/runtime/src/runtime/core/mod.rs`

## Travail

1. Definir `RuntimeEvent` avec au minimum `RewardCommit`.
2. Definir `RuntimeMutation` avec au minimum `Reward`.
3. Ajouter `RuntimeEventBus`.
4. Permettre l'enregistrement de handlers Rust.
5. Faire retourner une liste de mutations par dispatch.
6. Garder le bus testable sans host API et sans Lua.

## Contraintes

- Le bus ne doit pas logger directement.
- Le bus ne doit pas connaitre les offsets jeu.
- Le bus ne doit pas avoir de dependance a `mlua`.
- Les erreurs handler doivent etre collectees et retournees proprement.

## Tests a ajouter

- Un handler recoit un `RewardCommitEvent`.
- Deux handlers peuvent chacun produire une mutation.
- Une erreur handler n'empeche pas de savoir quel handler a echoue.
- Dispatch sans handler retourne une liste vide.

## Verification

Lancer:

```powershell
cargo test -p oppw4-sdk-runtime-plugin runtime::core::bus
cargo test
```

Resultat attendu: tous les tests passent.

## Definition of done

- Le bus existe et reste interne.
- Aucun hook jeu n'est encore modifie.
- Les handlers sont suffisamment generiques pour un futur frontend Lua.
