# Step 3.2 - IA 5 - Lua Rewards Frontend `on_commit`

## Objectif

Ajouter le frontend Lua minimal qui permet aux mods d'ecrire:

```lua
local rewards = require("sdk.runtime.rewards")

rewards.on_commit(function(ctx)
  if ctx.rank:contains({ "s", "s_plus" }) then
    ctx.rewards.berry:multiply(2)
  end
end)
```

Le handler Lua doit produire des mutations core. Le hook ne doit toujours pas
appeler Lua directement.

## Contexte a lire

- `official_plugins/sdk/runtime/src/rewards/lua.rs`
- `official_plugins/sdk/runtime/src/rewards/lua_tests.rs`
- `official_plugins/sdk/runtime/src/runtime/lua_module.rs`
- `official_plugins/sdk/runtime/src/runtime/core/rewards.rs`

## Fichiers a modifier

- Modifier: `official_plugins/sdk/runtime/src/rewards/lua.rs`
- Modifier: `official_plugins/sdk/runtime/src/rewards/lua_tests.rs`
- Modifier si besoin: `official_plugins/sdk/runtime/src/rewards/mod.rs`

## Travail

1. Ajouter `on_commit(callback)` au module Lua rewards.
2. Stocker les callbacks dans un registry frontend, pas dans le hook.
3. Construire un context Lua depuis `RewardCommitEvent`.
4. Convertir les actions Lua en `RewardMutation`.
5. Supporter seulement `berry:multiply(factor)` dans cette tache.
6. Faire `rank:contains(...)` sur slots ou aliases.

## Contraintes

- Pas de condition load-time piegeuse.
- `if ctx.rank:contains(...)` doit evaluer au moment de l'event.
- Les callbacks Lua doivent etre isoles par mod source si l'info existe.
- Une erreur Lua doit etre logguee et ne doit pas crasher le jeu.

## Tests a ajouter

- `on_commit` accepte une fonction.
- `rank:contains({"s", "s_plus"})` retourne vrai pour S.
- `berry:multiply(2)` produit `RewardMutation::MultiplyBerry(2.0)`.
- Une callback qui throw retourne une erreur controlee.

Resultat attendu: tous les tests passent.

- Elle compile vers des mutations core.
