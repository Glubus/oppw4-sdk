# Step 3.1 - IA 4 - Rewards Mutation MVP

## Objectif

Brancher le hook rewards existant sur le core event/mutation pour Berry, en
gardant le comportement actuel si aucun handler ne produit de mutation.

## Contexte a lire

- `official_plugins/sdk/runtime/src/rewards/commit_hook.rs`
- `official_plugins/sdk/runtime/src/rewards/commit_hook/format.rs`
- `official_plugins/sdk/runtime/src/rewards/control.rs`
- `docs/reverse-notes/difficulty-reward-ghidra-2026-05-20.md`

## Fichiers a modifier

- Modifier: `official_plugins/sdk/runtime/src/rewards/commit_hook.rs`
- Modifier: `official_plugins/sdk/runtime/src/rewards/mod.rs`
- Modifier si besoin: `official_plugins/sdk/runtime/src/runtime/core/rewards.rs`

## Travail

1. Construire `RewardCommitEvent` depuis les donnees deja observees dans le hook.
2. Dispatcher l'event dans le bus.
3. Appliquer uniquement `RewardMutation::MultiplyBerry`.
4. Ne pas toucher medals/items/crew points/souls dans cette tache.
5. Logger avant/apres pour Berry avec une ligne claire.

## Contraintes

- Si aucune mutation, les slots restent identiques.
- Si une mutation est invalide, ne pas crasher le result screen.
- Les souls restent explicitement non implementes.
- Le hook ne doit pas appeler Lua.

## Tests a ajouter

- Mutation berry `x2` transforme un montant connu.
- Multiplication preserve un montant absent.
- Multiplication est bornee si le type existant a un cap.
- Sans handler, le resultat est identique.

## Verification

Lancer:

```powershell
cargo test -p oppw4-sdk-runtime-plugin rewards
cargo test
```

Resultat attendu: tous les tests passent.

## Definition of done

- Le reward hook passe par le core event bus.
- Berry peut etre modifie par mutation Rust.
- Le chemin par defaut reste vanilla.
