# Step 3.3 - IA 7 - Logs, Signals Et Debug Validation

## Objectif

Rendre le nouveau pipeline observable sans lire les logs a la loupe pendant 20
minutes. Les logs doivent dire quel event est parti, quelles mutations ont ete
produites, et quelles mutations ont ete appliquees.

## Contexte a lire

- `official_plugins/sdk/runtime/src/runtime/signals.rs`
- `official_plugins/sdk/runtime/src/rewards/commit_hook/format.rs`
- `docs/API-SURFACES.md`
- `official_plugins/sdk/overlay/src/panels.rs`

## Fichiers a modifier

- Modifier: `official_plugins/sdk/runtime/src/runtime/signals.rs`
- Modifier: `official_plugins/sdk/runtime/src/rewards/commit_hook/format.rs`
- Modifier si besoin: `official_plugins/sdk/runtime/src/rewards/commit_hook.rs`

## Travail

1. Ajouter un log compact `reward_event`.
2. Ajouter un log compact `reward_mutations`.
3. Ajouter un signal JSON `sdk.runtime.rewards.event` si le signal bus le permet.
4. Garder les anciens logs reward utiles.
5. Ne pas spammer en dehors du result/reward commit.

## Contraintes

- Les payloads JSON doivent etre evidence-oriented.
- Pas de long dump par frame.
- Les noms publics doivent etre `rank`, `berry`, `mutations`.
- Les noms reverse peuvent etre dans `raw` si necessaire.

## Tests a ajouter

- Format log event stable.
- Format log mutation stable.
- Payload JSON serialisable.
- Aucun payload vide quand une mutation existe.

## Verification

Lancer:

```powershell
cargo test -p oppw4-sdk-runtime-plugin rewards runtime::signals
cargo test
```

Resultat attendu: tous les tests passent.

## Definition of done

- Les prochains tests jeu peuvent confirmer le pipeline sans deviner.
- Les logs distinguent event, mutation, application.
- Le signal est optionnel si le code existant ne permet pas un ajout propre.
