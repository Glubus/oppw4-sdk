# Step 1.1 - IA 1 - Inventaire Ownership Et Dette

## Objectif

Faire un inventaire court et actionnable de ce qui appartient au runtime core,
au frontend Lua, au data service, et aux probes reverse avant de deplacer du
code. Cette tache ne doit pas modifier le comportement du jeu.

## Contexte a lire

- `docs/LANGUAGE-INDEPENDENT-SDK-RUNTIME.md`
- `docs/CRATES-CLEANUP-AUDIT.md`
- `official_plugins/sdk/runtime/src/runtime/mod.rs`
- `official_plugins/sdk/runtime/src/rewards/mod.rs`
- `official_plugins/sdk/runtime/src/mission/rank/mod.rs`
- `official_plugins/sdk/runtime/src/mission/difficulty/mod.rs`
- `official_plugins/sdk/data/src/lib.rs`

## Fichiers a creer ou modifier

- Creer: `docs/language-independent-sdk-runtime/step-1/output/1-1-ownership-map.md`
- Ne pas modifier de code dans cette tache.

## Travail

1. Lister les modules qui sont deja runtime-core compatibles.
2. Lister les modules encore trop Lua-specifiques.
3. Lister les modules qui appartiennent au data service.
4. Lister les probes qui doivent rester read-only.
5. Signaler les fichiers trop gros seulement si ca bloque la suite.

## Format attendu

```markdown
# Runtime Ownership Map

## Runtime core

- `path`: role, pourquoi il reste dans `sdk.runtime`.

## Lua frontend temporaire

- `path`: role, dette exacte, frontend cible.

## Data service

- `path`: role, raison de sortir du runtime core si necessaire.

## Reverse probes read-only

- `path`: probe, config qui l'active, risque connu.

## Decisions pour Step 1

1. Decision courte.
2. Decision courte.
```

## Verification

Lancer:

```powershell
cargo test
```

Resultat attendu: tous les tests passent. Si un test casse, cette tache a
change trop de choses.

## Definition of done

- Le fichier `output/1-1-ownership-map.md` existe.
- Il contient uniquement des constats verifiables dans le repo.
- Aucun comportement runtime n'a change.
